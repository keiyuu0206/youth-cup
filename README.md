# youth-cup：少年サッカー大会の運営アプリ

U7〜U12 の大会を、日程作成から結果公開までスマホで運営するための Web アプリです。Cloudflare Workers と D1 で動きます。**すべてのファイルが1つのフォルダに並んだ構成**なので、GitHub の画面にまとめてアップロードするだけで使えます。

## できること

- **管理者**：大会の状態管理（準備中・公開中・開催中・終了）、URL と PIN の発行、カテゴリ設定（試合時間・昼休憩・コート数・形式・判定順）、形式テンプレート、チーム登録、条件付きランダム組み分け、日程の自動作成と入れ替え、結果の確定、抽選結果の入力、当日のコート単位の時間調整
- **関係者**：大会共通 PIN で入り、自チームの試合のスコアを仮登録（相手チームと本部にすぐ表示）
- **閲覧者**：確定結果、日程、順位表、トーナメント表、最終順位、自チームの絞り込み、検索、SNS 用カード

## ファイル構成

| ファイル | 役割 |

## ブラウザだけで公開する手順

### 1. GitHub にアップロード

1. GitHub で新しいリポジトリ `youth-cup` を作り、「uploading an existing file」を開きます。
2. このフォルダのファイルを**すべて選択**して、ドラッグ＆ドロップ（またはファイル選択画面で全選択）します。
3. 「Commit changes」を押します。

### 2. データベースを作る

1. Cloudflare のダッシュボードで「ストレージとデータベース」→「D1 SQL データベース」→「作成」を選び、名前を `youth-cup-db` にします。
2. 表示された**データベースID**をコピーしておきます。
3. 「コンソール」タブに、GitHub 上の `schema.sql` の中身をすべて貼り付けて実行します。
4. GitHub で `wrangler.jsonc` を編集し、`REPLACE_WITH_YOUR_D1_DATABASE_ID` をコピーした ID に置き換えて保存します。

### 3. 公開する

1. Cloudflare の「Workers & Pages」→「作成」→「リポジトリをインポート」で `youth-cup` を選びます。
2. プロジェクト名は `youth-cup`、ビルドコマンドは空欄、デプロイコマンドは `npx wrangler deploy` にしてデプロイします。
3. 作成された Worker の「設定」→「変数とシークレット」で、種類を「シークレット」にして次の2つを登録します。
   - `ADMIN_PASSWORD`：管理画面のログインパスワード
   - `SESSION_SECRET`：英数字を40文字以上でたらめに並べたもの
4. `https://youth-cup.〇〇.workers.dev/admin` を開いてログインします。

以後、GitHub 上でファイルを編集・アップロードすると自動で再公開されます。

## 公開リポジトリでの注意

- `ADMIN_PASSWORD` と `SESSION_SECRET` はシークレットとして登録し、ファイルに書かないでください。
- `wrangler.jsonc` のデータベースIDは秘密情報ではないので、公開して問題ありません。
- `LICENSE` は MIT のひな形です。`<著作者名>` を書き換えるか、別のライセンスに差し替えてください。

## 無料プランの目安

Workers の無料プランは 1 日 10 万リクエストまでです。閲覧画面は 20 秒ごとに更新を確認するため、1人が 8 時間開き続けると約 1,450 リクエストになります。同時に 60 人程度までが目安で、それを超える大会では有料プラン（月 5 ドル）にしてください。画面を閉じている間や裏に回している間は更新を止めています。

## 大会当日の流れ

1. 前日までに「公開中」にし、閲覧 URL を保護者へ、結果登録 URL と PIN を各チームへ送る（「LINE用の案内文をコピー」が使えます）
2. 当日の朝に「開催中」にする
3. 届いた結果を「結果」タブで確定する。終了予定を過ぎて未確定の試合は赤く表示される
4. 遅れが出たら、その試合の「時間をずらす」でコートごとに調整する
5. 全試合が終わったら「終了」にする

## 仕様メモ

- 勝点は勝ち 3・引き分け 1・負け 0。判定順の既定は 勝点 → 得失点差 → 総得点 → 当該対戦成績 → 抽選 で、大会ごとに並べ替えられます。
- 一部のチームだけ順位が決まった場合、残りのチームはその次の基準から比べます。
- 抽選まで並んだ場合は「抽選待ち」と表示し、管理者が「順位」タブで入力します。
- 決勝トーナメント（クロス方式）は組の数が 2・4・8 のときに使えます。予選の組の全試合が確定すると自動で対戦チームが入ります。
- 確定後に予選結果を修正した場合、未開始の試合は自動で差し替え、結果登録済みの試合には警告を出します。

## 全体管理者と地域管理者

- **全体管理者**：ログインIDは `admin`（Cloudflare の変数 `ADMIN_ID` で変更可）、パスワードはこれまでどおり `ADMIN_PASSWORD` です。すべての大会を操作でき、右上の「アカウント管理」で地域管理者の発行・停止・パスワード再設定と、地域ごとの利用状況（開催回数など）を確認できます。
- **地域管理者**：全体管理者が発行したIDとパスワードでログインします。機能は全体管理者と同じですが、見える・操作できるのは自分が作った大会だけです。右上の「パスワード変更」で自分のパスワードを変えられます。
- 形式テンプレートと要項のプリセットは、各管理者が自分用に作れます。全体管理者が作ったものは、一覧で「地域管理者に公開」にチェックしたものだけが、地域管理者に「共通」として表示されます。
- **スコア管理者**：全体管理者・地域管理者が、右上の「スコア管理者」から発行します。結果の承認（修正・差し戻し・入力を含む）だけを行えるアカウントで、ログインするとスマートフォン向けの専用画面が開きます。担当する大会を限定することもできます。
- パスワードは PBKDF2-SHA256（10万回）で保存しています。変更・再設定・停止をすると、その管理者のほかの端末のログインはすぐに無効になります。
- 複数の地域で利用する場合は、Cloudflare の Workers Paid プラン（月5ドル）を推奨します（無料枠は全地域で共有され、1日の上限に達すると全地域のサイトが止まるため）。

## 品質とセキュリティ

- `npm test`：日程作成・組み分け・トーナメント・順位計算のテスト
- `npm run test:fuzz`：チーム数・組数・コート数・形式・日数をランダムに変えた600通りの大会を最後まで進め、時間の重なりが無いこと、全試合が確定できること、最終順位が設定どおり決まることを確かめる総当たり検査
- `npm run test:e2e`：サーバーを通した通しテスト（`npm run dev` の起動中に実行）

セキュリティ上の主な対策：管理APIはすべてログイン必須、ログイン状態は改ざん検知付きの Cookie（HttpOnly・Secure・SameSite）、他サイトからの書き込みの拒否、PIN とパスワードの試行回数制限、データベースへの命令はすべてプレースホルダ、画面への文字の表示はすべてテキストとして扱う、外部スクリプトを読み込ませない Content-Security-Policy、スポンサーのリンク先は https/http のみ。
